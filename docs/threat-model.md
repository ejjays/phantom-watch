# Threat model

Audience: anyone who sideloads the APK. There is no payment. Comments use
anonymous or Google sign-in, so the app holds an account identity and profile
fields on the device.

## What the app holds

| Secret | Where it lives | Extractable from the APK? |
|---|---|---|
| TMDB key | `local.properties` -> `BuildConfig` | yes |
| OpenSubtitles key | `local.properties` -> `BuildConfig` | yes |
| Supabase anon key | `local.properties` -> `BuildConfig` | yes (it is an anon key) |
| Google Web Client ID | `local.properties` -> `BuildConfig` | yes (public id) |
| Groq keys | `local.properties` -> `BuildConfig` | yes |
| Deepgram key | `local.properties` -> `BuildConfig` | yes |
| Telemetry key | `local.properties` -> `BuildConfig` | yes |
| Relay key and fallback URL | `local.properties` -> generated by `web/build.gradle.kts` | yes, in the wasm bundle |
| OTA signing key | held off-repo, Actions secret as backup | no |
| Release keystore | held off-repo | no |
| FCM service account | Actions secret, used by `scripts/notify.mjs` | no |

The keys in the first block are public to anyone who has the APK or the wasm
bundle. They only buy quota. If a key starts costing money, move that feature
behind the Worker instead of hiding it in the app.

## Community data

Comments use Supabase Auth. `Social.kt` stores the access token, refresh token,
user id, expiry, name, email and picture in `community` preferences.
`GoogleAuth.kt` gets the Google ID token through Credential Manager and sends
it to Supabase. The app sends comments, votes and reports through Supabase
RPCs, and row level security owns the write rules. Watch positions and cached
config stay in separate prefs and are not backed up.

## What is protected

- The OTA config is signed with ECDSA P-256 and verified against a pinned
  public key. A tampered bundle is rejected and the last accepted one stays
  in prefs. The private key is kept off-repo, with the Actions secret as the
  backup; installed devices never receive it.
- Telemetry carries TMDB ids, per-leg counts and timings, the picked format
  label, its height, subtitle and audio flags, and the config version. It
  carries no titles, stream URLs or account data.
- The app's own data (watch positions, cached config) is not backed up
  (`allowBackup="false"`).
- Updates are fetched from the project's GitHub release URL over https,
  following at most four redirects that stay on GitHub hosts, inside a size
  cap. The APK must have the same package, a non-lower `versionCode`, and the
  same signer as the installed app; release builds also pin the release
  certificate in `UPDATE_CERT_SHA256`. A foreign APK signed with the old debug
  key is rejected.
- Debug builds also take an APK from loopback, so `scripts/install.sh`
  installs without a tap. The activity is exported only in the debug manifest,
  the url must be `http://127.0.0.1:<port>/app-*.apk` with no query, and the
  request must carry the 32-byte token from the intent. `UpdateTrust.localEntry`
  answers false whenever `BuildConfig.DEBUG` is off, so a release build keeps
  the GitHub-only rule above.

## Known exposures, accepted on purpose

- Losing the release keystore ends updates for installed release builds. I
  keep it off-repo and back it up offline, twice. The same applies to the OTA
  signing key.
- Cleartext traffic is off. Every provider, API and media host is https; an
  `http://` stream will not load until its host is added to
  `res/xml/network_security_config.xml`.
- The provider WebView bridge loads a local `https://phantom.local/` blob with
  network loads blocked. Only the signed script runs in it, and the bridge can
  issue HTTP requests, so it is only as trustworthy as the signed script.
- The trailer WebView is a second WebView with a different setup.
  `TrailerBridge.kt` loads a `https://www.youtube.com/` document with network
  loads enabled, injects the bundled `app/src/main/assets/trailer.js` and a
  `window.__trCfg` object from signed config, and fetches youtubei.js and
  bgutils-js from public CDNs. It has its own `http` bridge with a 25 s
  deadline. The script config is signed; the CDN code is not.
- Provider keys in `providers.json` are the provider's own obfuscation values,
  published in the bundle by necessity.

## If the audience grows

1. Move TMDB, OpenSubtitles, Groq and the telemetry key behind the Worker and
   hand the app short-lived tokens.
2. Pin the certificate of the config endpoint, the Worker and Supabase.
3. Rate-limit the telemetry endpoint and drop the shared key.
4. Review the community write paths and rate limits before opening sign-in to
   the public.
